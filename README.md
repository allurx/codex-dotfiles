# codex-dotfiles

个人 Codex 全局协作指令的私有版本仓库。

## 文件与作用域

- `codex/AGENTS.md`：全局指令的唯一维护源。
- 本机生效文件：Codex 主目录中的 `AGENTS.md`；默认是 `%USERPROFILE%\.codex\AGENTS.md`，设置了 `CODEX_HOME` 时以该目录为准。
- 只管理明确纳入版本控制的配置文件，不复制或同步整个 Codex 主目录。凭据、会话、记忆、日志、缓存和部署备份均不入库。

## 修改与交付

1. 核对工作区、维护源、生效文件及 `AGENTS.override.md` 覆盖关系，保留已有修改。
2. 按授权修正 `codex/AGENTS.md`，检查冲突、重复和变更范围，准备完整可审阅的 diff。源文件修改不自动包含部署、提交或推送。
3. 获得部署授权后，先确认源与目标没有未经处理的新变化，创建本机文件的时间戳备份，再替换生效文件并逐字节核对。已有明确部署授权时，不增加重复确认步骤。
4. 按授权创建本地 commit；只有获得推送授权时才 push。部署、commit、push 可以由同一明确请求连续授权，也可以分别执行。

Git 提交和推送不会自动替换本机文件，部署也不会自动提交仓库。需要用户决定时，先完成独立工作并准备可审阅结果。流程由 AI 执行和验证，不维护额外的部署脚本。

## 验证与恢复

- 提交前核对工作区和最终 diff；只暂存本次目标文件，审查 staged diff，并运行 `git diff --cached --check`。
- 部署后比较仓库源文件与本机文件的内容，在新 Codex run 或任务中验证加载。旧任务中重新读取只能证明文件已保存，不能证明启动指令链已更新。
- Git 历史保留已提交版本，本机时间戳备份保留替换前的状态。恢复或重新部署旧版本前，仍需相应授权并核对准确目标，保留已有修改。
- 项目特有约束保留在对应项目中，可复用的长流程放入 Skill；此仓库中的全局文件只保存跨项目的长期规则。

加载机制参考：[官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。
