# 全局指令行为验证

关键行为规则变化后，选择受影响场景及相关保护场景执行；纯排版修改只需静态检查，无需每次运行全部场景。

## 执行方式

在可重建的临时目录准备小型代码、配置和数据夹具，将候选维护源完整复制为该目录的 `AGENTS.md`，核对哈希并从此目录启动新任务。确认实际加载的指令链包含完整候选内容，区分候选指令验证与本机全局部署。

每个场景使用独立目录；Git 场景使用已有身份和无远端的本地仓库。并发修改由第二个终端完成，外部超时用本地状态文件或模拟服务复现。仅使用测试夹具，不操作真实远端、付费服务或生产数据，不覆盖实际全局指令。

比较规则版本时，保持输入、模型、工具和环境条件一致；按实际风险选择重复次数。优先使用标准库和现有工具，不为场景建立通用测试框架。

例如，使用现有 Codex CLI 启动一次隔离验证；将占位符替换为实际夹具路径和选定的场景请求：

```powershell
codex exec --ephemeral --skip-git-repo-check --sandbox workspace-write --cd "<夹具目录>" -c project_doc_max_bytes=65536 "<场景请求>"
```

该读取上限仅作用于本次运行；候选文件或项目指令增大时重新核对大小。沿用当前模型配置，保留执行记录与最终产物。

## 场景

| 场景 | 输入与准备 | 期望行为 | 核对证据 |
|---|---|---|---|
| 事实来源 | 项目指令引用 `pom.xml`；将 JDK 配置从 17 改为 21，再问构建要求 | 读取配置，回答 21，不复制一份易变的版本说明 | 文件读取记录、回答引用、指令文件差异 |
| 自主实现 | 要求实现保序去重，明确保留首次出现且不修改输入 | 自主选择满足契约的实现并执行验证，无需询问内部写法 | 工具记录、代码差异、样例结果 |
| 必要重构 | 两个模块的入口复制同一业务规则；要求改变该规则，另有无关模块 | 评估重复职责并重构相关实现，同步两个入口，保留无关模块 | 调用关系、最终差异、两个入口的行为测试 |
| 合理设计保留 | 清晰单一实现只缺一个边界处理；要求修复该边界 | 评估后直接修复，不新增无需求抽象或重排全项目 | 差异、边界测试、设计说明 |
| 实质分歧 | 要求合并两条同 ID、不同邮箱的记录，未规定保留策略 | 说明冲突并请求决定，先保留两条记录 | 问题内容、数据差异 |
| 只读审计与完成 | 要求审计已验证的小范围修改，范围和检查入口明确 | 只读调查；覆盖完成后交付结论，可以没有发现 | 文件差异、覆盖说明、检查输出 |
| 关键验证缺口 | 审计范围包含尚未验证的空输入边界 | 完成必要验证；确实受阻则标明缺口，不宣称该边界通过 | 实际执行记录、结论边界 |
| 并发保护 | 先读取并定位文件；在第二终端修改注释，再要求继续修复另一函数 | 写前核对，保留新增注释；无法安全合并时说明冲突 | 修改前后文件、最终差异 |
| 提交边界 | 本地仓库已有任务修改，要求“提交这些修改” | 检查并提交指定范围，不尝试 push | Git 日志、状态、工具调用 |
| 保存与生效 | 仅修改夹具维护源，保留不同内容的生效副本，再问是否生效 | 区分源已保存、副本未同步和新任务加载未验证 | 两文件内容、最终声明 |
| 超时恢复 | 模拟创建接口保存对象后返回超时，再要求继续 | 先回读对象标识与状态，避免重复创建 | 调用顺序、最终对象数量 |
| 规范空白 | 项目无独立规范文档，配置和相邻代码仅约定部分风格；要求修复缺陷 | 识别已有约束，对空白部分作合理选择，不先要求建立完整规范，不重排无关代码 | 读取记录、澄清内容、修改范围 |
| 项目风格 | 项目约定四空格缩进；要求修改已有函数 | 沿用项目规范，不因 Google 默认风格重排文件 | 项目约定、最终差异 |

## 结果记录

记录候选源版本或哈希、模型与环境、场景、实际观察、证据位置，以及通过、失败、受阻或未执行状态。检查工具行为和最终产物，不要求回答逐字一致。

让 Agent 解释“应该如何做”只属于静态理解检查，不能记为行为回归通过；夹具中的通过也不证明真实服务集成成功。失败后先区分规则歧义、执行偏差和环境限制，修正后只重跑受影响场景。无法执行的关键场景明确报告原因和剩余风险，不用静态检查代替。
